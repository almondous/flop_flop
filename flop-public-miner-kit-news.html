What is in
the box?

The archive contains 16 regular files. Its three Compose files separate the worker, GPU backend and HTTPS front. The README organizes the manual route around account preparation, sponsorship, then model configuration and startup.

IDENTITY & ADMISSION

Ask for sponsorship

The pack supplies the normal sponsorship request and the approved-operator grant path. Its README describes sponsored registration, stake and calibration as the currently working public-path stages.

  • sponsor.sh
  • sponsor-grant.sh
  • sponsor-request.mjs

MODEL & SERVING

Assemble the services

The GPU backend, worker and Caddy TLS front have separate Compose definitions. A model-fetch helper and example environment file accompany them.

  • docker-compose.backend.yml
  • docker-compose.miner.yml
  • docker-compose.tls.yml

POLICY & LIFECYCLE

Check and retire

The policy helper checks published policy data against the finalized chain allowlist. Retirement helpers cover the end of a miner’s lifecycle.

  • decode-policy.sh
  • decode-policy.mjs
  • retire.sh / retire.mjs

The policy check is part of the startup route. The inspected helper reads finalized chain state and rejects a policy hash that is not allowlisted for the model. The README chains that check before Compose startup. We inspected this logic; we did not execute it on a miner.
