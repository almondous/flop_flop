FLOP’s public miner manual adds a bounded host self-check. Its stopping point is explicit: healthy local services and a reachable endpoint do not establish gateway listing or paid work.

New manual content verified against our November 13 capture.

A diagnostic gets a defined boundary.The change is public operating guidance. No new runtime activation or successful deployment is established here.

The miner and validator guides now carry a November 12 update label and point operators to a network-specific setup guide. Compared with the pages we captured on November 13, the miner text adds a self-check sequence, precise public-endpoint rules, GPU-topology guidance and a separate warning about spendable fees.

Start at the first failed check.

The guide describes self-check.sh as read-only: it does not restart, sign or rotate anything, and prints no credential. Its ordered checks run from local services to finalized registration and calibration, then through public DNS and endpoint observations. JSON output is documented for agents.

It exits nonzero on a FAIL. Operators are told to fix the first failing check; the worker republishes its endpoint ad every five minutes, so that step does not require a reinstall. The manual also notes that probing one’s own hostname from the host can differ from an outside probe because of hairpin NAT.

  • What it observesServices, authenticated local readiness, finalized registration/calibration, DNS, an anonymous 401, a fresh info-proof challenge and the last endpoint advertisement.
  • What it leaves openIt does not verify the proof signature or capacity bond, and cannot see gateway listing. A successful check is not evidence of accepted paid work.

Count GPUs. Then count serving ranks.

The new text separates the stock backend’s all-GPU visibility from TENSOR_PARALLEL_SIZE, which selects serving ranks and defaults to one. Seeing eight devices therefore does not establish eight serving ranks. Capture and calibration must be validated on the actual model/GPU topology before admission.

Stake and transaction fees have different jobs.

Locked stake

Sponsored stake is locked for staking. It cannot be transferred or used to pay transaction fees or inference charges.

Spendable funds

The separate fee grant is spendable funding, but ongoing fee coverage is not guaranteed. Repeating sponsorship is not a promised fee refill.

When spendable funds run short, the updated manual says to pause new work through the supported operator procedure, reconcile existing obligations and preserve account, worker state and settlement evidence. It directs operators to authorized funding rather than another account or repeated sponsorship to bypass limits.

A public hostname is part of admission.

The guide now specifies a canonical lowercase DNS hostname, optionally with a nondefault port, without a scheme, path or explicit port 443. Every resolved address must be public and the trusted HTTPS certificate must match. Admission refuses private/CGNAT addresses and redirects; the worker origin stays on loopback.

The linked operator guide also requires network identity, reviewed software and admission inputs to travel together. Devnet instructions do not configure testnet or mainnet. A network marked planned has no supported setup path yet.

What we verified

We compared the live official pages with our prior capture. The new paragraphs above are absent from that capture; the guides’ date labels are not proof of a deployment time. This reports newly observed documentation changes, not another release of the previously covered miner kit.

The guide now points to the 20261110 manual pack. Our normal HTTP retrieval of its README/archive returned 403, and the browser blocked the README request. We did not verify that archive’s checksum or script implementation, run a GPU host, test admission or make a paid request.
