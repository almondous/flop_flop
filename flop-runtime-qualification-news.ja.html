RUNTIME COMPATIBILITY / 2026年11月8日確認

runtimeは進んだ。
SDKは止めた。

FLOP devnetの確定済み状態はruntime spec 1014014を返す。一方、公開SDKの最新版は0.4.0のままで、対応リストにこの値がない。CLI 0.4.0による残高読み取りは、この確認で停止した。

チェーンの新しい状態が、同じパッケージの使える範囲を変えた。

FLOPPER FEEDは同じ公式devnetの正規ブロックを2つ照合した。ブロック3087243のspecは1014003、確定済みブロック3162251は1014014。そのうえでクライアント側の対応確認を行う配布コードを調べた。コードは同じでも、現在のruntimeは宣言された集合の外にある。

2つのブロック。
異なるruntime。

1014014はチェーンのruntime specVersion、0.4.0はSDKパッケージの版番号だ。SDKは明示的なリストへの所属を確認するため、数値が大きいことや近い値が載っていることだけでは対応済みにならない。

NPM / LATEST = 0.4.0

CLIで実際に起きたこと

導入済みCLI 0.4.0はSDK 0.4.0を使っている。残高コマンドはCOMMAND_FAILEDで終了し、下のメッセージを返した。SDK実装は、runtimeが対応リストにない場合にRUNTIME_INCOMPATIBLEを発生させる。

CLI 0.4.0 / SDK 0.4.0

flop --network devnet balance ADDRESS --json

Unsupported runtime spec version 1014014

ADDRESSはプレースホルダー。実アカウント、認証情報、署名用の情報は含めていない。

検証できた範囲

確認済み確定済みruntimeは1014014。npm latestはSDK 0.4.0。その対応リストに1014014はなく、CLIの残高読み取りは拒否された。
対象範囲今回示したSDK経由のチェーン操作経路が対象。すべてのgateway APIやCLIコマンドが利用不能だとは確立していない。
未確定runtimeが切り替わった正確なブロック、1014014内部のプロトコル変更、新たに対応確認されたSDKの公開は、この調査では確認していない。
互換性の主張guardは維持した。取引への署名・送信、未対応runtimeへの書き込みは行っていない。
