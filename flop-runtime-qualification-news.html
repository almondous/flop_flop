RUNTIME COMPATIBILITY / VERIFIED 08 NOV 2026

Runtime moved.
SDK says no.

FLOP devnet reports runtime spec 1014014 in finalized state. The latest published SDK is still 0.4.0, and its qualification list does not contain that version. A balance read through CLI 0.4.0 stops at this check.

A new chain observation changes what an unchanged package can do.

FLOPPER FEED read two canonical blocks from the same official devnet. Block 3087243 reports spec 1014003; finalized block 3162251 reports spec 1014014. We then checked the package that performs the client-side compatibility check. Its code is unchanged, but the live runtime is outside its declared set.

Two blocks. A different runtime.

1014014 is the chain’s runtime specVersion. 0.4.0 is the SDK’s package version. SDK compatibility is an explicit membership test, so neither a larger runtime number nor a nearby listed version grants support.

What the CLI actually did

The installed CLI 0.4.0 uses SDK 0.4.0. Its balance command exited with COMMAND_FAILED and the message below. The SDK implementation raises RUNTIME_INCOMPATIBLE when the runtime is absent from its qualified list.
