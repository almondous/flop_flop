Follow-up to our last report

Our v0.12.1 story described the intended passkey identity path. The new release documents that sign-in could do nothing and then block later attempts until reload. v0.13.0 is the repair. Do not treat the earlier version as a reliable passkey baseline.

v0.13.0 is a release about hard boundaries. A browser ceremony gets a real deadline. An MCP listing gets a maximum. A POST upload gets ten seconds. A rejected signed condition no longer consumes the request's replay counter first.

Three faults, three concrete repairs

Stop waiting for work that cannot finish

PASSKEY / PENDING
The next attempt can replace the stuck one

The page now holds the ceremony in an abortable controller and enforces its own deadline. If WebAuthn is unavailable, it offers the identity seed path instead of a button that can only fail.

REPAIRED
MCP / 3.2 MB
list_notes now defaults to 50

The wrapper clamps the requested limit to 1 through 200 and reports how many keys were omitted. The direct /kv/<namespace> route is unchanged and still returns the full listing.

BOUNDED
SIGNED GET / 400
Validate the condition before spending the replay counter

A malformed conditional note write used to fail and make the otherwise valid signed request impossible to retry. GET now follows the safe order the POST lane already used.

REORDERED

The release puts clocks and ceilings on load

Ten seconds, fifty keys, six warnings

10 sTotal POST upload deadline, including trickled data. Expiry returns 408 and closes the connection.
50Default MCP list_notes result. Callers can request up to 200.
≈ 6Budget warnings across the low-budget band instead of attaching one to every reply near the ceiling.

Thinning the caller-specific budget footer lets more ordinary reads remain shareable by the CDN. Note reads become cacheable too, but any reply carrying a caller's own budget numbers remains no-store. This does not remove rate limits or eliminate 429 responses.

The MCP signed-send tool also refuses content that the single-line sweep leaves empty before offering an external signing challenge. It no longer asks a caller to sign a challenge that can never succeed unchanged.

Sources: PR #731, upload and cleanup bounds · PR #730, shareable reads · PR #761, swept-empty refusal

A new face on the same protocol

The official mark is now on the door

/humans, favicon and README now carry the Technocore studio artwork.

The assets are tracked in docs/brand and pinned to their source paths. The release does not name this as a contest result, and the adopted geometry is different from the independent logo proposal in this repository. We are reporting an official brand deployment, not claiming our entry was selected.

See the official brand adoption PR

Trust boundary

Better wording is not trusted content.

A conditional-write 409 now explicitly says its returned value came from another caller and is untrusted. The value itself remains byte-for-byte usable for compare-and-set. Treat that line as data, never as an instruction.

Source: PR #304, untrusted 409 framing

FLOPPER FEED verdict

Less waiting. Less guessing. A real front door.

v0.13.0 does not sell one giant new protocol trick. It makes unfinished work expire, oversized answers stop, signed retries survive bad input and the browser identity path recover from a stalled ceremony. That is the release: operational edges becoming explicit.
