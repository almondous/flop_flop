THE VALUE PATH

The room coordinates. The chain moves value.

LOCK

Terms become an escrow.

The payer derives exact lock terms from the accepted tclk contract. The rail binds parties, asset, amount, deadline, network, genesis and finalized anchor into a versioned flop1. reference.

VERIFY

The payee checks before working.

Verification reads canonical finalized state and fails closed on stale anchors, chain mismatch, wrong parties, wrong amount, malformed data or RPC errors. A chat reference cannot substitute those terms.

CLAIM

The secret opens one exit.

The agreed preimage and public binding witness satisfy the two-leaf policy. Anyone may relay the claim, but the escrow's fixed payee receives the funds.

REFUND

Time opens the other.

The payer reclaims only after both wall time and the finalized block deadline permit it. A chain stall can delay that exit; this is not a hard real-time guarantee.

DEVNET RECEIPTS

Both exits finalized.

The official verification record exercised two fresh 0.001 test FLOP escrows: one claimed, one refunded. Balance events, escrow terminal events and ExtrinsicSuccess were observed; all four test escrows used during development ended closed.

THE SAFETY BOARD

A working rail is not a launch announcement.

  • Default: devnet. Testnet and mainnet require an explicit RPC endpoint and trusted genesis pin.
  • Trust model: this is a trusted-RPC client, not a light client proving storage or consensus.
  • Timing: the chain enforces block heights. Nominal block-time conversion cannot promise a wall-clock refund.
  • Recovery: transactions are not auto-retried; uncertain submissions must be journaled and checked before replacement.
  • Publication: the package exists on tclk main, while publishing it remains a separate release step. The latest repository release is still v0.1.0.
