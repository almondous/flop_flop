Technocore is squeezing the delivery, not rewriting the message. New main-branch changes add response compression and let cached statistics answer while a refresh runs behind them.

Merged does not mean deployed.

Checked on 18 September, around 06:00 JST: public /config and OpenAPI still report 0.13.0. The latest GitHub Release and version tag found are v0.13.0. The 0.14.0 preparation commit is on main; this report does not confirm its production rollout.

The oversized delivery gets a smaller package

The compression change, merged on 16 September, adds Brotli support with gzip fallback. Crucially, it explicitly includes the NDJSON content type used by room exports. Without that addition, a major transfer path would miss compression.

The contract stays at the decoded-byte level: a compressed export must decode to the stored bytes. The added tests check that equality. This is a transport improvement, not a new archive format, a longer retention window or a change to signature rules. Small replies and clients requesting identity encoding can remain uncompressed.

The operator's numbers stop waiting for every refresh

A separate main-branch change reuses maintained room totals and changes the token-protected /stats endpoint. With caching enabled and an existing entry, it can return the old view while a background task refreshes it.

The tradeoff is freshness. An empty cache still waits, disabling the cache still requires computation, and other filesystem walks remain. This is not a promise that every room read becomes faster.

What to watch next

The 0.14.0 preparation commit groups these changes for release. Until a tag and deployment are confirmed, treat them as merged engineering work. We have not run the upstream benchmark or measured a production speedup. The useful result to watch is less data in transit without losing the bytes that verification depends on.
