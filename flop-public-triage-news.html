The backlog
gets a clock.

FLOP Labs has committed a daily triage slot for five public repositories. A rotating slice of open issues and pull requests gets classified; narrowly defined duplicate or already-answered issues can be closed. Contributor queues now have a scheduled inspection.

Changes landed 5 November 2026 · Checked 6 November, JST

48

At most 48 items per run. The scan rotates through each repository’s open backlog. Issue closures are capped at five; pull requests can receive labels and remain open.

Five repos.
One shared action.

The callers pin the same context-aware classifier commit. Their daily schedules are staggered. The shared implementation lives in FLOP Labs’ .github repository, which also has its own caller.

What passes through
the sorter?

The new revision adds context to classification. A title alone can misdescribe a PR’s actual purpose or hide a documentation contradiction inside a question.

READ

Public context

Issues supply their title, body and item type. Eligible PRs also supply changed filenames. The classifier does not receive diff hunks or check out contributor code.

  • Incomplete file lists, over 100 changed files, or PR context above 32,000 bytes cause abstention.
CLASSIFY

Labels with a fallback

With a configured TypeSafe key, Jev can judge the principal purpose of the change. Regression-test-only PRs are treated as other; contradictory documentation can route to documentation.

  • Without that key, conventional-title rules, simple repost detection and the curated FAQ still work.
  • Existing type choices take precedence. A label previously removed is not simply added back.
RESOLVE

Closures with limits

Automatic closure is restricted to issues. A duplicate must resolve to an older, open defect in the same repository; a curated FAQ answer must match current public documentation.

  • Paraphrased duplicates need shared code identifiers, text overlap and a high-confidence equivalence judgment.
  • Assigned or discussed defects, reopened issues and individual access requests are protected from automatic closure.

A label is still
just a label.

This action does not review, approve or merge a pull request. It does not establish that a reported fix is correct. Maintainers and contributors still own technical review and the next code change.
