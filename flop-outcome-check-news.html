RELEASE CHECK / 11 NOV 2026SDK 0.5.2 / CLI 0.4.4

A LOST REPLY
MEETS THE LEDGER.

CLI 0.4.4 changes what a gateway tools probe does after an ambiguous cooperative close: inspect finalized channel events, and preserve an unknown result when the evidence runs out.

A transport failure cannot tell you whether the channel settled. The new probe follows the channel into finalized history instead of turning that uncertainty into a second close.

FLOPPER FEED checked the public npm artifacts for SDK 0.5.2 and CLI 0.4.4 against their SHA-1 and SHA-512 registry integrity values. These are fresh package publications after our CLI 0.4.2 report. The important changes here are outcome reconciliation, backup resume-state placement and canonical session-pallet names.

OUTCOME RECONCILIATION

What the probe now checks

The published CLI captures a finalized starting height before attempting the cooperative submission. Even when that attempt throws, it scans forward for the same channel within the probe deadline. A candidate event must belong to a successful extrinsic.

  • A

    Settled evidence must match aggregate work, carry the cooperative flag and report positive miner payment.

  • B

    A matching TimedOutRefunded event returns a refund result. Mismatched work and zero miner payment are reported separately.

  • C

    An unavailable starting head or an exhausted scan preserves an explicit unknown outcome with a do-not-resubmit instruction.

Scope matters: this change is in gateway tools qualification probes. It does not establish a universal repair for every direct session or resolve every public settlement report.

OFFLINE VERIFICATION

Seven local controls.
No live close.

We extracted the unchanged reconcileProbeClose and settleProbe functions from the verified CLI bundle and ran seven offline controls with synthetic RPC events, a synthetic clock and submission counters. All seven matched the stated expectations.

A lost submission reply followed by matching finalized settlement produced success with one submit call and zero force-close calls. Refund, wrong work, zero payment, absent outcome and unavailable initial history followed their distinct paths. The separate pre-submission allowance-refusal control made zero cooperative submissions and one force-close call.

This is an extracted-function check. It is not a full CLI run, cryptographic receipt verification, live paid probe or chain settlement demonstration.

The other new package changes

CLI 0.4.4 / BACKUP

Resume state stays with the checkpoint

CLI 0.4.4 places download receipts beside --model-dir by default. A supplied --state-dir must be on the same filesystem; the inspected code checks device identities. Metadata-only onboarding now includes the registered precision in its suggested backup command.

The streaming backup route itself was introduced in 0.4.2. Today’s new detail is the receipt location and the precision carried into the handoff.

SDK 0.5.2 / SESSION HTLC

Canonical session-pallet names

SDK 0.5.2 resolves flopSessionKeys and FlopSessionKeys before legacy aliases when creating session-bound HTLCs. Its changelog retains spending prechecks, signer-specific nonce handling and wrapper errors. We inspected the published alias resolver; we did not submit a signed HTLC.

CLI 0.4.3 raised its SDK dependency floor to 0.5.2; 0.4.4 keeps that floor. The earlier 30/120-second enrollment deadlines are unchanged. The cached expired-allowance path still asks for operator renewal.
