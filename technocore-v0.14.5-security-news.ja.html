Technocore v0.14.5が本番へ入った。最大の修正は、悪意あるWebページがDNS rebindingを使ってローカルMCPを操作する経路を遮断したこと。同じreleaseで、所有権・cache・E2E keyの境界も締め直している。

Technocore v0.14.5 · 2026年9月24日

今回切断された経路

これまではWebページが自分のhostnameをloopbackへ向け直し、same-originのようにローカルtechnocore-mcp --httpを操作できる余地があった。

外部の
Webページ信用できないorigin
→
DNS
rebindhostnameをloopbackへ変更
→
署名鍵を持つ
local MCP利用者の端末にある署名surface

修復された4つの境界

Gate 01 / loopback

不正なHostと外部Originを拒否

loopbackで動くMCP HTTP wrapperは、確認済みのloopback addressかlocalhostだけを受け付ける。remote pageからlocal portを署名oracleやopen proxyとして使う経路を塞いだ。

Gate 02 / ownership

新しいroom ownerは空のallow-listから始める

以前のownerが消えても、植え付けられたallow-listだけが残る場合があった。今後、未所有のd- roomを最初にclaimした人が古いkeyを引き継ぐことはない。

Gate 03 / cache

Host由来のdocumentへVary: Host

固定のpublic URLを設定していない場合、requestのHostからURLを作るcache可能なdocumentはVary: Hostを返す。他人のHostを含む内容が共有cacheから配られるのを防ぐ。

Gate 04 / E2E

Pattern 4は署名済みkey recordだけを信頼

E2E patternは、DID note内の署名されたe2e: recordへだけsealし、暗号化ごとにrandom nonceを使う。誰でも書ける裸のkey fieldでroom keyの送り先を差し替えることはできない。

対応が必要な人

ローカルでtechnocore-mcp --httpを動かすなら、wrapperを0.14.5へ。

修正はhosted chatだけでなくMCP wrapper側に入っている。PyPIでもtechnocore-mcp 0.14.5を確認済み。hosted Workerは別のremote-security境界を使うため、このloopback問題の対象ではなかった。
