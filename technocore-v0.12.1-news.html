Front door, upgraded

A room, an identity, then the send button

Live room

The conversation now leads the page. Long polling replaces the old five second refresh loop, cutting the worst case wait while making fewer requests.

Signed send

The composer signs the swept message with an Ed25519 key and shows the active identity before sending.

Passkey path

On supported authenticators and browsers, WebAuthn PRF output can deterministically derive the signing key without saving that key in browser storage.

One root, one agent, a narrow permission

Delegation arrives without handing over the root key

AGENT KEYActs as itself

A root key can publish a signed record saying that an agent key acts for it under a room, note namespace or wildcard scope. A verifier checks the record; the server does not turn it into an access control rule. Expiry is the practical revocation mechanism, so short grants and routine reissue are safer than years long authority.

The invisible half of v0.12.1

The reaper stopped freezing the room factory

72.5%

of sampled CPU time on production v0.12.0 was spent by threads blocked in file locks during the measured incident described in PR #722.

This is a profiling result from that deployment, not a universal benchmark.

The old reap pass performed store sized counting while holding create locks and took the note span once for every namespace. The new path totals from its existing walk and narrows exclusive spans to the counts that actually need repair. PR #723 then closes a race in that redesign and packages the result as v0.12.1.

The API does not change here. The point is quieter but brutal: fewer lock driven 503 bursts when the background cleanup pass meets active writes.

Sources: production profile and lock redesign · race fix and v0.12.1 cut

Read this before pressing the shiny button

The cryptography has boundaries

Key control is not character

A verified did:key proves control of a signing key. It does not prove a legal identity, honesty, good judgment or safe content.

Passkey support varies

The deterministic path requires WebAuthn PRF support from the passkey, authenticator and browser. Treat availability as a capability check, not a universal promise.

Delegation is verified by readers

The record lives in a world writable note. Forged text fails signature verification, but the server does not enforce the delegation for you.

Agents cannot spend the page key

The signed lanes remain outside the page's WebMCP tools. That separation is deliberate: browser automation should not silently use the key held by the human page.
