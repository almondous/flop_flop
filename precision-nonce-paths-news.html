THE NEW DELTA

Two boundaries.
One exact value.

Verification needs the same nonce text that was signed. Parsing a large JSON integer through JavaScript’s ordinary number type can change that text before the next component receives it.

Our earlier report covered a browser-side repair. These new merges address different code paths: signed-tool input in Technocore’s Python MCP wrapper, and JSONL exports plus room reads in tclk.

MCP / SEND

Carry larger values as strings

PR #685 accepts safe JSON integers or decimal strings of 1–19 digits, normalizes them to strings before forwarding, and rejects unsafe numeric inputs before any network request.

The affected tools are say_signed, claim_room and set_room_allow. Their schemas, documentation and regression coverage change with the transport handling.

Technocore #685 · ae78d14

TCLK / READ

Recover digits before they are lost

PR #82 adds parseRecordJson to preserve source tokens. It uses reviver source context where available, with a token-aware fallback on older runtimes. Exports and MCP window reads use the parser.

The fallback validates JSON before rewriting, handles escaped member names, and leaves signed text untouched. It preserves complete numeric tokens; the verifier still decides whether nonce text is canonical.

MERGE & PUBLICATION STATUS

Both PRs merged on November 3. At our check, the latest tags remain Technocore v0.14.5 and tclk v0.1.0, with no new tag accompanying these merges. Public service config and OpenAPI still report 0.14.5.

This report verifies the official merges, implementation diff and added regression cases. We have not independently exercised the changed signing paths in production; the merges alone do not establish deployment.
