CLI 0.5.0 / SDK 0.6.0

CLI 0.5.0

A new command for an existing authority.

FLOP published CLI 0.5.0 and SDK 0.6.0 on npm on November 12. The new CLI exposes flop model mirrors set: the model publisher can change the registered list of download hints without changing the model’s content root. The command checks publisher identity against finalized chain state.

This makes the backup handoff more concrete. The earlier streamed-backup release prepared the data; this release adds a first-class mirror command and lets a metadata-only onboarding run reach approval once the required DA binding is already in place.

Locate, bind, then check.

Choose the locations

model mirrors set

HTTPS, Hugging Face, ModelScope and DA references are supported. A DA reference must resolve to a live Leased blob; its provider comes from finalized state. The final nonempty list holds up to eight entries. --clear removes the list.

--append preserves the finalized entries and adds missing ones. If every requested source is already present, the command returns unchanged. It reads and then replaces the list, so a concurrent change by the same publisher can be overwritten.

Bind before approval

model onboard --approve

For a metadata-only run, approval requires the registered model and its bound DA weights. The documented handoff is backup, upload by commitment, append the DA file-table mirror, then rerun approval. Missing binding stops the metadata approval path before chain writes.

Mirror URLs remain hints. Neither a registrar nor Root can use this command to take over the publisher’s mirror update authority.

Inspect the plan

--dry-run

The mirror command can validate and print an encoded unsigned call without submitting it. Its output includes the finalized registered list, requested list and additions.

After an uncertain submission, the documented recovery is to inspect the finalized list before resubmitting. No model-changing command was executed for this report.

Two chunks are a sample.

Before a new metadata-only approval, the CLI samples two random chunks of the bound DA image. It checks chunk commitments, relevant whole-file SHA-256 values, file fragments against the pinned Hugging Face revision, and padding. It rereads the approval evidence and refuses a changed image or table.

The release explicitly describes this as a spot check. It is not a proof of the entire model. Paid admission still stops at independent-audit-unavailable.

Capacity becomes inspectable

CLI 0.5.0 also adds miner capacity-rate show, backed by SDK 0.6.0 capacity-reservation reads at the finalized head. The SDK admits runtime specs 1014015 through 1014020; our public RPC read returned 1014020. This is compatibility scope, not evidence that a miner or inference job has passed qualification.

Unknown stays unknown

SDK 0.6.0 removes automatic faucet POST retries after ambiguous outcomes and adds detailed refused/unknown results. A sufficient wallet balance alone is no longer treated as proof of an attributable grant. Its detailed funding helper keeps even an accepted response unknown without an authenticated request-to-transaction binding.
